# Dutiful Daily Devotional — Design Spec (MVP v2.0)

| Version | Change |
|---------|--------|
| v1.0 | Initial MVP brief (working title "Daily Light"), Christian only, 30 entries, online study via bible-api.com |
| v1.1 | Renamed to "Dutiful Daily Devotional" |
| v2.0 | Multi-faith (Christian, Jewish, Muslim, Humanist), fully offline, OPSEC privacy defaults, 90 entries per tradition |

Status: **Approved design** (2026-11-01). Next step: implementation plan.

## 1. Purpose and audience

A daily reflection app for **U.S. service members of multiple faiths and none**, released publicly on the App Store. A home screen / lock screen widget shows a short daily passage and theme; tapping it opens the app for a deeper study session.

The app must work identically **with no network connection** (deployed, ship-borne, airplane mode for OPSEC) and must not reveal usage, location, or faith affiliation through network traffic or careless lock-screen display.

### Success criteria
- Every feature works in airplane mode on first launch after install.
- The app contains no networking code and makes zero network requests.
- A user can pick their tradition in under 10 seconds on first launch and change it later.
- Lock screen shows nothing faith-identifying by default.
- Each tradition's content has been reviewed by a qualified reviewer from that tradition before release (process requirement; tracked in `docs/CONTENT_REVIEW.md`).

## 2. Constraints

- SwiftUI, Swift 5.9+, **iOS 17.0 minimum**.
- Targets: `DutifulDailyDevotional` (app), `DutifulDailyDevotionalWidget` (WidgetKit extension), `DutifulDailyDevotionalTests`.
- Project generated by **XcodeGen** (`project.yml`); no hand-written `.xcodeproj`.
- Bundle ID placeholder `com.example.dutifuldailydevotional`; App Group `group.com.example.dutifuldailydevotional`.
- Display name "Dutiful Daily Devotional" (short name "Dutiful Devotional" if truncated).
- **No networking, no accounts, no analytics, no ads, no third-party SDKs.**
- **Public-domain source texts only.**
- No military seals, insignia, or branch logos.
- System fonts (SF), Dynamic Type, VoiceOver, light + dark mode.
- No force unwraps in production code.
- Development happens on Windows; builds and tests run on a **GitHub Actions macOS runner**.

## 3. Traditions and source texts

| Tradition | `Tradition` case | Source text | Study view unit | Reference format |
|---|---|---|---|---|
| Christian | `christian` | World English Bible (WEB), public domain | Chapter | `John 14:27`, `Philippians 4:6-7` |
| Jewish | `jewish` | JPS 1917 Tanakh, public domain | Chapter | `Psalms 46:2`, `Joshua 1:9` |
| Muslim | `muslim` | Qur'an, M. M. Pickthall translation (1930), U.S. public domain since 2026-01-01 | Surah | `Qur'an 2:286`, `Qur'an 94:5-6` |
| Humanist | `humanist` | Marcus Aurelius, *Meditations* (George Long, 1862); Epictetus, *Enchiridion* (George Long, 1877); Seneca, *Moral Letters* (R. M. Gummere, 1917–1925) | Book / chapter / letter | `Meditations 4.3`, `Enchiridion 5`, `Seneca, Letters 13.4` |

Notes:
- JPS 1917 versification follows the Hebrew text (e.g. Psalm superscriptions are verse 1). References in Jewish entries use JPS numbering.
- Public-domain status must be re-verified for every App Store territory before release (see §11).
- Source files are converted to bundled JSON by build-time scripts in `scripts/`; the app never downloads text.

## 4. Content model

### 4.1 Shared daily themes
There are **90 day slots**. Each slot has one theme (e.g. "Courage") and **one entry per tradition** for that theme. All users see the same theme on the same day, each in their own tradition's voice. This keeps tone consistent across traditions and lets reviewers compare one theme side by side.

Themes are chosen to be broadly relevant to service life (courage, fear, grief, loneliness, separation from family, duty, rest, gratitude, forgiveness, integrity, hope, endurance) and to avoid doctrinally divisive or polemical topics, including passages about warfare against other faiths.

### 4.2 Devotional entry (`Shared/Resources/Devotionals/<tradition>.json`)
```json
{
  "_reviewNote": "Content requires human review by a qualified reviewer from this tradition before release.",
  "tradition": "christian",
  "entries": [
    {
      "day": 1,
      "theme": "Peace",
      "reference": "John 14:27",
      "passageText": "<exact text from the bundled source>",
      "reflection": "<2–3 sentences>",
      "studyPrompts": ["<question>", "<question>", "<question>"]
    }
  ]
}
```
- `day` is 1…90 and identical across the four files for the same theme.
- `id` is derived: `"\(tradition)-\(day)"` (e.g. `christian-1`). It keys favorites and journal notes.
- `passageText` must match the bundled full text for `reference` (enforced by a test, §9).

### 4.3 Full texts (`DutifulDailyDevotional/Resources/Texts/<source>/…json`)
App target only (the widget never needs them). One JSON file per book/surah/work:
```json
{ "work": "John", "divisions": [ { "number": 14, "verses": [ { "number": 27, "text": "..." } ] } ] }
```
Estimated ~9 MB uncompressed total.

## 5. Daily selection

`index = dayOfYear % entries.count` (dayOfYear is 1-based, local calendar), computed in `DevotionalProvider`, shared by app and widget so they always agree. Entry chosen is `entries[index]` sorted by `day`.

Known, accepted behavior: at year rollover the last 5 days (6 in leap years) repeat entries that reappear on Jan 1–6. Covered by tests.

### Backlog (do not build)
Interfaith rotation mode, additional traditions (Buddhist, Hindu, Latter-day Saint, Sikh), notifications, user-selectable refresh time, audio, iCloud sync, Android, accounts, localization.

## 7. Privacy and OPSEC

- **Zero networking.** No `URLSession`, no web views, no remote assets. CI fails if `URLSession`, `WKWebView`, or `http://`/`https://` URLs (other than in license/about text) appear in Swift sources.
- **Storage split:**
  - App Group `UserDefaults`: `selectedTradition`, `discreetLockScreen` only. Readable by widget.
  - App-private SwiftData store (not in App Group): `FavoriteMark`, `JournalNote`. File protection `.complete`; store directory excluded from iCloud/iTunes backup.
- **Privacy manifest** (`PrivacyInfo.xcprivacy` in both targets): `NSPrivacyTracking = false`, no tracking domains, no collected data types, required-reason API `NSPrivacyAccessedAPICategoryUserDefaults` with reason `1C8F.1` (App Group defaults).
- Widget never displays journal content.
- Sharing is always user-initiated via the system share sheet.

## 8. Architecture

```
Shared/  (compiled into app + widget)
  Tradition.swift            enum + display names + source attribution
  Devotional.swift           Codable entry, derived id, shareText
  DevotionalStore.swift      loads/decodes per-tradition JSON from a Bundle
  DevotionalProvider.swift   today's entry for (tradition, date, calendar)
  UserPreferences.swift      App Group UserDefaults wrapper
  AppConstants.swift         App Group id, URL scheme, widget kind
  Resources/Devotionals/{christian,jewish,muslim,humanist}.json

DutifulDailyDevotional/
  App/        DutifulDailyDevotionalApp.swift, DeepLink.swift
  Views/      RootView, OnboardingView, TodayView, DevotionalCardView, StudyView,
              PassageTextView, FavoritesView, ArchiveView, SettingsView, NeedToTalkView
  Persistence/UserDataModels.swift, ModelContainerFactory.swift
  Scripture/  SourceReference.swift (parse references per tradition)
              LocalTextStore.swift  (load a division and mark highlighted verses)
  Resources/  Texts/{web,jps1917,pickthall,stoics}/..., Assets.xcassets, PrivacyInfo.xcprivacy

DutifulDailyDevotionalWidget/
  DutifulDailyDevotionalWidgetBundle.swift, DevotionalWidget.swift,
  DevotionalTimelineProvider.swift, Views/{Small,Medium,LockScreen}WidgetView.swift,
  PrivacyInfo.xcprivacy

DutifulDailyDevotionalTests/
scripts/      build-time converters (source text → JSON); never shipped
.github/workflows/ios.yml
```

Dependencies flow one way: Views → Provider/Store/LocalTextStore → models. `DevotionalProvider` takes `Calendar` and `Date` as parameters so it is deterministic in tests. `LocalTextStore` takes a `Bundle` so tests can use fixtures.

### Error handling
- Missing or malformed bundled JSON is a build defect, caught by tests; at runtime the store returns an empty result and views show a neutral "Content unavailable" state rather than crashing.
- An unparseable reference shows the passage alone without chapter context.
- No user-facing network errors exist, by construction.

## 9. Testing

XCTest, run on the macOS CI runner on every push:
- **DevotionalProvider:** index for Jan 1, Dec 31 (365 and 366), Feb 29, year rollover, local-midnight boundary in a non-UTC time zone; app and widget code paths return the same entry.
- **Decoding:** all four devotional files decode; each has exactly 90 entries with days 1…90; themes for the same day match across traditions; every entry has 3 non-empty prompts.
- **SourceReference:** parsing for all four formats, ranges, numbered books (`1 John 4:19`), invalid input.
- **LocalTextStore:** loads a division, highlights the right verses, handles missing files.
- **Content integrity:** every devotional's `reference` resolves in the bundled full text and `passageText` matches it (whitespace-normalized).
- **No-network guard:** CI grep step (§7).

## 10. Deliverables

1. `project.yml` + full source tree; `xcodegen && xcodebuild build test` passes on the CI macOS runner for the iOS Simulator.
2. `README.md`: setup (Windows + CI, or Mac), App Group configuration, adding/editing entries, regenerating source texts.
3. `docs/CONTENT_REVIEW.md`: per-tradition review checklist and sign-off table.
4. Summary of assumptions and unverified items.

Content is delivered in two batches: days 1–45 for all four traditions, then days 46–90.

## 11. Risks and open verification items

- **Public-domain status** of each translation in every target App Store territory: needs legal confirmation before release.
- **Content accuracy and sensitivity:** reflections are AI-drafted; each tradition requires review by a qualified reviewer (e.g. a chaplain of that faith).
- **Source text acquisition:** depends on downloading public-domain files (eBible.org, Sefaria, Project Gutenberg, etc.); Project Gutenberg license headers must be stripped from shipped text.
- **App name:** "Devotional" may read as primarily Christian; revisit before release.
- **No local Xcode:** all compile feedback comes from CI; expect a few fix-up iterations.
